================================================================================
ESTRUCTURA DE DATOS
================================================================================

users (tabla principal)
  ├─ id (ID del usuario)
  ├─ email (correo)
  ├─ created_at (fecha registro)
  ├─ email_verified_at (email verificado)
  │
  ├─► model_has_roles → roles (relación de roles)
  │    └─ name = 'tutor' o 'student'
  │
  ├─► profiles (tabla de perfil)
  │    ├─ first_name (nombre)
  │    └─ last_name (apellido)
  │
  └─► user_identity_verifications (verificación de identidad)
       ├─ status (0=pendiente, 1=aprobado, 2=rechazado)
       ├─ attachments (JSON: {"front":"...", "back":"..."})
       ├─ personal_photo (foto personal)
       └─ created_at (cuando se subió)

La discrepancia de números (574 vs 470) se debía a que:
- Tu web cuenta TODOS los tutores (574)
- Pero solo muestra como "disponibles" los que aceptaron términos (~470)
- Los scripts SQL no filtraban por terms_accepted_at

✅ SOLUCIÓN V3:
- Nuevo script: SCRIPTS_SQL_TUTORES_VERIFICACION_V3.sql

================================================================================
CÓMO LA APP CUENTA TUTORES
================================================================================

1. HomeController::getUserCounts()
   → Tutores TOTALES: +574
   → Método: whereHas('roles', where 'name' = 'tutor')
   → Sin filtro adicional

2. HomeController::countTutorsWithAcceptedTerms()
   → Tutores DISPONIBLES: ~470
   → Método: + whereNotNull('terms_accepted_at')
   → Solo los que aceptaron los términos de servicio

DIFERENCIA: 574 - 470 = 104 tutores sin aceptar términos
